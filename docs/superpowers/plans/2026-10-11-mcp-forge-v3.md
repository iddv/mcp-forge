# MCP-Forge v3 Plan: MCP 2026 + plugins & skills

**Goal:** Bring generated projects up to date with the MCP spec (2025-06-18 → 2025-11-25 → 2026-07-28)
and the `mcp` Python SDK 2.x, add the newer protocol features as `mcp-forge add` features, and add
distribution features (Claude Code plugin, Agent Skill, MCPB bundle, MCP Registry `server.json`).
mcp-forge itself also ships as a Claude Code plugin with a skill.

## Why (research summary)

- `mcp` 2.0 (2026-07-28) renamed `FastMCP` → `MCPServer` and **removed** `mcp.server.fastmcp`.
  Generated projects pin `mcp[cli]>=1.6.0`, so a fresh install today resolves 2.3.0 and the
  generated `server.py` fails with `ModuleNotFoundError`. **This is the critical fix.**
- Spec 2026-07-28 is stateless: no `initialize` handshake, and server→client requests (elicitation,
  sampling, roots) became Multi Round-Trip Requests (`InputRequiredResult`). In SDK 2.x the portable
  way is `Annotated[T, Resolve(fn)]` with `Elicit` / `Sample` / `ListRoots`; raw `ctx.elicit()` raises
  `NoBackChannelError` on 2026 connections and stateless HTTP.
- Logging, Sampling, and Roots are deprecated in 2026-07-28, with a 12-month removal window. Tasks
  moved to an extension that the Python SDK doesn't implement yet, so there's no `tasks` feature.
- New since the current snippets were written: tool annotations, `title` fields, structured output
  (`outputSchema`), resource templates (RFC 6570), completions, icons, resource links, URL-mode
  elicitation, sampling with tools, lifespan, Streamable HTTP, auth with `TokenVerifier` and
  `validate_token_resource`, and the MCP Apps extension (`ui://` resources).

## Changes

### 1. Target SDK 2.x (breaking → mcp-forge 3.0.0)
- `server.py.tpl`: `from mcp.server.mcpserver import MCPServer`, `MCPServer("name", instructions=...)`.
- `pyproject.toml.tpl`: `mcp[cli]>=2.3,<3`.
- `test_server.py.tpl`: in-memory `Client(mcp)` (no subprocess) on the 2026-07-28 protocol.
- Fix existing snippets:
  - `context` uses the async API; progress plus stdlib logging (`ctx.info` is deprecated).
  - `elicitation` uses `Resolve` + `Elicit` and handles decline/cancel via `ElicitationResult`.
  - `auth` is a real `TokenVerifier` subclass plus `AuthSettings(validate_token_resource=True)`
    over streamable-http.

### 2. New protocol features (`mcp-forge add <feature>`)
| Feature | Adds |
|---|---|
| `annotations` | Tool with `title`, `ToolAnnotations` (read-only/destructive/idempotent/open-world hints) |
| `structured-output` | Tool returning a pydantic model → `outputSchema` + `structuredContent` |
| `resource-templates` | `@mcp.resource("users://{user_id}/profile")` parameterised resource |
| `completions` | `@mcp.completion()` handler for prompt/template argument autocompletion |
| `sampling` | Tool that asks the client's LLM via `Resolve` + `Sample` |
| `roots` | Tool that reads client roots via `Resolve` + `ListRoots` |
| `lifespan` | Typed lifespan context (startup/shutdown resources) accessed via `ctx` |
| `media` | Image content + `ResourceLink` results |
| `http` | Streamable HTTP entry point (`--http`), `/health` custom route, stateless mode |
| `apps` | MCP Apps extension: `ui://` HTML resource bound to a tool, with text fallback |

Each snippet carries a marker comment (`# --- mcp-forge:<feature> ---`), so `add` is **idempotent**
(re-adding is a no-op with a warning). Some features need imports or constructor changes (lifespan,
apps, auth). The snippet engine gets an optional `imports` section, hoisted to the top of
`server.py`, and a `server_kwargs` rewrite of the `MCPServer(...)` call. This avoids the current
"comment that tells the user to edit the constructor" approach.

### 3. Distribution features (file generators, not snippets)
| Feature | Generates |
|---|---|
| `plugin` | `.claude-plugin/plugin.json`, plugin `.mcp.json` using `${CLAUDE_PLUGIN_ROOT}` and `uv run`, and `.claude-plugin/marketplace.json` so the project repo is installable via `/plugin marketplace add` |
| `skill` | `skills/<name>/SKILL.md`: an Agent Skill teaching Claude when and how to use this server's tools (auto-included by `plugin`) |
| `mcpb` | `manifest.json` (MCPB 0.4, `uv` server type) for one-click Claude Desktop install |
| `registry` | `server.json` for the official MCP Registry (PyPI package, `uvx` runtime hint), plus the `mcp-name` README marker |

`Feature` gains a `files` map (template → output path) alongside `snippet`. Existing files are never
overwritten.

### 4. mcp-forge as a Claude Code plugin
- Repo root: `.claude-plugin/plugin.json` + `.claude-plugin/marketplace.json`.
- `skills/mcp-forge/SKILL.md`: tells Claude how to scaffold and extend servers with mcp-forge
  (feature catalogue, which feature to pick for which need, and the testing workflow).
- Install: `/plugin marketplace add iddv/mcp-forge` → `/plugin install mcp-forge@mcp-forge`.

### 5. CLI
- `mcp-forge add a b c` takes several features; `mcp-forge features` lists them with descriptions,
  grouped as protocol vs distribution.
- `new --with` accepts every feature.

### 6. Tests
- Unit: snippet insertion, idempotency, import hoisting, constructor rewrite, file generation, JSON validity.
- **Integration** (skipped when `mcp` isn't installed): scaffold a project, add *every* feature,
  import the generated `server.py`, and exercise each feature through an in-memory `Client`
  (list tools, call tools, read templates, complete, elicitation and sampling via client callbacks).
  This proves the snippets actually run against SDK 2.x.
- CI installs `mcp` so the integration tests run.

## Additions after manual testing
- `errors` (`ToolError`), `notifications` (subscriptions/listen + list_changed), `middleware`, `docker`.
- `http` reads `MCP_HOST`/`MCP_PORT` from the environment, so `auth` advertises the right resource URL
  (`MCP_PUBLIC_URL` overrides it). `MCP_REQUEST_STATE_KEY` configures `RequestStateSecurity` for multi-replica deployments.
- Server `version` in the template.

## Out of scope
- URL-mode elicitation: 2026-07-28 removed `elicitationId` and the SDK has no portable (`Resolve`) form yet.
- Tasks (no Python SDK support yet), Server Cards (format not final), SSE transport (deprecated).
